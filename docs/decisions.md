## 2026-09-30: Economy core
- `Ledger` is pure state + rules (unit-tested): a move checks everything first (amount, fee, locks, funds, overflow, `maxBalance`), then changes both sides. `EconomyService` wraps it with events, saved data, stats, history, log and client sync, in that order, after the ledger move.
- Infinite accounts (`tradery:server`) take part in moves without balances: paying from one creates money, paying into one destroys it. Stats classify every move: emission, burn, cash out/in (coin items).
- `/eco set` is a deposit/withdraw of the difference, so events, log and stats see it.
- Accounts passed in by other mods are resolved by id to this world's account (an `Account` object from an earlier singleplayer session never writes into a stale ledger).
- The world's currency decimals are stored in `tradery:accounts` on first start; a different value in the config later is ignored with a warning.
- Saved data lives on the server storage (`server.getDataStorage()`, files in `data/tradery/`), `DataFixTypes.SAVED_DATA_COMMAND_STORAGE` as the no-op fixer.
- Transaction log: JSON lines written on a daemon thread after commit; `server_start` marker on every start; old files deleted by `log.retentionDays`.

## 2026-09-30: Config
- Own JSON5 reader/writer (`config/Json5`) on Gson's tree; numbers become `BigDecimal`, so money values keep every digit.
- Every field is lenient (a broken value falls back to its default) but always written; `ConfigDiff` compares the file with the decoded config and logs each dropped value or unknown key, so typos are reported instead of silently ignored.
- `server.json5` and `rewards.json5` are written only when missing; `client.json5` is rewritten by the game (HUD toggle), comments are regenerated from the code.

## 2026-09-30: Permissions
- Fabric: Fabric API's `fabric-permission-api-v1` (`CommandSourceStack`/`Entity` implement `PermissionContextOwner` through interface injection): `checkPermission(tradery:<path with />, fallback PermissionLevel)`. LuckPerms 5.5.85 maps `tradery:balance/others` to `tradery.balance.others`.
- NeoForge: `PermissionAPI` nodes `tradery.<path>`, registered in `PermissionGatherEvent.Nodes`; the default resolver checks the player's op level. Non-player sources (console, command blocks) use their own permission level.

## 2026-09-30: Networking and HUD
- Payload channels are optional on NeoForge; the server sends only to clients that have the channel. Clientbound payloads are handled on the client thread (`TraderyClient.handle`).
- `/tradery hud` is a server subcommand that sends `HudTogglePayload` (no client command sharing the `/tradery` root).
- HUD: Fabric `HudElementRegistry.attachElementBefore(CHAT)`, NeoForge `registerBelow(VanillaGuiLayers.CHAT)`. Hidden with F1 (`gui.hud.isHidden()`), with any screen open (`gui.screen()`), and until the server sent `CurrencyInfo` + the balance. A bottom-corner panel that would overlap the hotbar area moves above it.
- The HUD coin is pixel art generated by `tools/textures.py` (textures as code, no external assets).
- The HUD shows the number without the currency symbol (balance and popups): the coin icon already stands for it.
- Tradery's screens and the Jade tooltip show amounts as coin + number too (`MoneyText`): an object text component (`AtlasSprite`, GUI atlas, 8x8 glyph `tradery:icon/coin`) forced to white so text colors don't tint it; `getString()` falls back to the symbol. Chat and command replies keep the configured symbol.

## 2026-09-30: Vending
- Trades are menu button clicks (`clickMenuButton`) instead of a custom `VendingBuy` payload: vanilla already checks the click belongs to the player's open menu; the menu checks distance (≤ 8 blocks) and the rate limit (10/s). The only custom C2S is `VendingSavePayload` (the money price); goods, price item and facade are the server's own copies of the sample slots.
- Sample ("ghost") slots copy the cursor stack and never take it; clicks are handled in `clicked()` on both sides, so the client prediction matches.
- The owner edits a draft (data slots + sample slots); "Save" validates (blacklist, facade rules), posts `VendingConfiguredEvent`, applies, and closes every buyer screen of that block when the offer changed — nobody pays a price they didn't see.
- Buyer screens get stock and affordability through two data slots (16-bit, capped at 9999), recomputed in `broadcastChanges`.
- Contents drop in `BlockEntity#preRemoveSideEffects` (removal, not unload), which also closes the menus and updates the vendor index.
- Protection: destroy progress 0 for strangers; creative-mode instant breaking is blocked through Fabric `PlayerBlockBreakEvents.BEFORE` / NeoForge `BreakBlockEvent`; `PushReaction.IMMOVEABLE`; bedrock-level blast resistance.
- Facade: rendered by the block entity renderer with `BlockModelResolver`, squeezed into the base; the blockstate `facade=true` hides the default base model.
- NeoForge GameTest mock players don't have `neoforge:advanced_open_screen`; for such connections menus open the vanilla way (server-side menu is identical).
- Screens are drawn with fills (`Panels`), no GUI textures.
- Case proportions (thinned twice after review): base 3 px (vending: coin slit and stock light) / 2 px (display), glass up to the 1 px frame at 15-16 px. `VendingBlock.BASE_HEIGHT` / `DisplayBlock.BASE_HEIGHT` drive the shapes, the facade height and the item's height (middle of the glass); `tools/assets.py` has the same numbers.
- Both cases are glass on top too: a 2 px metal frame holds a flat glass pane one pixel below its top (the pane has an up and a down face, so it shows through the walls). Walls and top use `tradery:block/case_glass` (faint tint + streaks) instead of vanilla glass, which is almost fully transparent and made the top look open.

## 2026-09-30: Quick trade and look-at hint
- Researched the predecessors' code (original Vending Block 1.6.4–1.12.2, Restocked): no-GUI trading by clicks, and an own look-at box at the top of the screen (not a WAILA plugin). Holding right-click repeats only through vanilla's 4-tick use repeat.
- The author's call: sneak + use buys, sneak + attack sells (buyback blocks), holding repeats; a plain use still opens the buyer window. The owner's sneak + click stays vanilla (so the owner can still break the block).
- Client side: the click is taken before vanilla acts (Fabric `UseBlockCallback` returning FAIL on the client, `ClientPreAttackCallback`; NeoForge `InputEvent.InteractionKeyMappingTriggered`), so a held block isn't placed and nothing is mined. Attack fires every tick and use every 4 ticks while held; `QuickTradeInput` sends at most one `VendingQuickTradePayload` per 4 ticks. On NeoForge the `RightClickBlock`/`LeftClickBlock` events weren't enough: a cancelled use still sends the vanilla packet, and a survival attack only fires once.
- Server: reach (`isWithinBlockInteractionRange(pos, 1.0)`), loaded chunk, the block entity, the trade rate limit (10/s), then `VendingTrades.execute(…, 1)`. The action bar adds up a streak (same block, same direction, ≤ 30 ticks apart): "Bought 20 × Bread for (coin)12.50". Sounds: experience-orb ding for a trade, dispenser click for a refusal (vanilla sounds, no new assets).
- Hint layout (reworked after review: the first version was too wide and mixed alignments): a vanilla tooltip card (`TooltipRenderUtil.extractTooltipBackground`), everything centered: owner, "Sells [icon] for [price]" with counts drawn on the icons and no item names, then the keys. Names and item tooltips only while sneaking. Keys use short names for the usual bindings ("Shift", "RMB"/"ПКМ"), the game's name otherwise; the "RMB: window" part was dropped.
- Hint: rows cached per target (position, settings object, admin flags, owner, STOCKED, sneaking, currency) and rebuilt only on change. "Sold out" comes from the STOCKED block state; the buyback-side reasons (owner broke, block full) are only known on the server and show when you try.

## 2026-09-30: Money sources
- Coin ore payout lives in `CoinOreBlock#getDrops`: players, explosions and machines all come through it, so no path skips the rules. The loot table decides the coin count (data packs can add Fortune); the block decides where the money goes.
- Coin ore textures are overlays on vanilla `block/stone` / `block/deepslate` (two coplanar elements, like grass block sides): no vanilla pixels are copied into the mod.
- Coins are money in the world: withdrawals and coins minted by non-player mining add to "cash in the world", deposits subtract (stats, inflation damping).
- `ore.dailyCap` limits direct mining; coins dropped by explosions/machines aren't capped (they need automation or TNT). Known and accepted.
- Rewards hook through common mixins (craft: `ResultSlot`, fish: `FishingHook#retrieve`, advancement: `PlayerAdvancements#award`, spawner tag: `EntityType#loadEntityRecursive`, placed marks: `BlockItem#placeBlock`, coin pickup: `ItemEntity#playerTouch`) and loader events for kills and block breaks. A GameTest loads every mixin target.
- `rewards.json5` sections are `{ enabled, rewards: { key: {min, max, chance} } }` instead of the spec's flat map: each type can be switched off without deleting its entries. `max` defaults to `min`, `chance` to 1.
- Blocks moved by pistons lose their "placed" mark (the mark is per position). `mine` rewards are off by default and the config comment says so.
- Server config and rewards config have test-only setters used by GameTests, restored in `finally`.

## 2026-09-30: Integrations
- Plugin classes for Jade/JEI/REI live in `common/.../compat` and are loaded only by those mods (Fabric entrypoints `jade`, `jei_mod_plugin`, `rei_client`; NeoForge annotations `@WailaPlugin`, `@JeiPlugin`, and `@REIPluginClient` on a subclass in the NeoForge module, since that annotation ships only in REI's NeoForge jar). Nothing else references them.
- Jade 26.x rejects a provider that is both a data provider and a component provider (crashes the game): stock data and the tooltip are two classes. Found by the `-Pcompat` client run.
- Recipe viewers set samples through `GhostSamplePayload`; the server accepts it only for an active sample slot of the player's open, valid Tradery menu. Samples are copies, so a client-made stack can't create items.
- Common Economy API is shipped with `include` (Fabric jar-in-jar); money moved through it is a normal Tradery transaction with reason `tradery:bridge/common_economy`.
- REI's API needs Architectury and Cloth (basic-math) on the compile classpath only.

## 2026-10-06: Release checks, automated
- The manual checklist became runnable checks. NeoForge has no client test framework, so a dev-only test mod (`neoforge/src/clientTest`, mod id `tradery_client_test`) drives a real client: creates a flat world through the Create World screen, holds the real key mappings through the normal tick (the mouse is grabbed first: vanilla only continues an attack with a grabbed mouse), checks items and money on the integrated server, takes screenshots, quits; a failure halts with exit code 1. MDG loads every mod of `mods {}` into every run by default, so the standard runs list only `tradery`.
- Fabric: `NetworkClientTest` uses the client GameTest dedicated server, so all payloads and the block entity sync go through their codecs (singleplayer skips serialization); Bob, a `FakePlayer` that joined the economy, is the second player. `PerformanceClientTest` measures `MinecraftServer#getAverageTickTimeNanos` and `Minecraft#getFrameTimeNs` (the test client draws once per tick, so wall time per frame only shows the 50 ms tick).
- **Found: trades were saved apart from their chunk.** Minecraft 26.3 writes a changed chunk on its own ~10 s after the change (`ChunkMap#saveChunksEagerly`), but server saved data and player data only at the autosave (5 min) or on stop. After a crash the stock was newer than the money (the first `kill -9` run: stock after the trades, balances before) — a buyback could duplicate goods, a sale lose them. Fix: `TradePersistence` remembers which players traded at which chunk; a mixin on `ChunkMap#save(ChunkAccess)` (every chunk write: eager, unload, autosave) then calls `SavedDataStorage#scheduleSave` (snapshots all dirty server data in that tick) and `PlayerList#save` for those players (invoker mixin). Verified with `tools/crash-test.sh` (real `kill -9` of a dedicated server, then a second launch checks one consistent state) and a negative control: without the hook the same run fails with a mixed state.
- **Found: NeoForge showed a "Mods loaded with 1 warning" screen** before the title screen: `logoFile` is deprecated in NeoForge 26.3. `neoforge.mods.toml` uses `iconFile` (the icon is square).
- The wrong-button message (sneak + attack on a selling block and vice versa) is now the client's own, with the hint's short key names, and no request is sent; the server keeps its check and message for other clients.
- Create and Mekanism have no 26.3 builds (Modrinth, 2026-10-06: latest 1.21.1). `coin_ore_not_processable` asserts what their machines rely on: coin ore blocks/items are in no `c:ores`/`raw_materials`/`dusts`/`ingots`/`nuggets` tag, no smelting or blasting recipe takes ore or coins.
- `ore_feature_places_ore` tries the vein up to 10 times: a random blob in a 5x5x5 stone cube can miss it.

## 2026-10-09: Economy lifecycle order
- Found while porting to 1.20.1 (the Forge crash-test mod used the API in its own `ServerStartedEvent` listener and sometimes ran first): the economy starts on the server-started event, so an addon calling `TraderyEconomy` in the same event could see "economy is not available", depending on the mod order. Now the economy starts before other listeners (NeoForge `EventPriority.HIGHEST`; Fabric: event phase `tradery:economy` ordered before `Event.DEFAULT_PHASE`) and stops after them on server stopped (`LOWEST` / a phase after the default one). Same on every version branch.

## API notes (26.3)
- `ResourceLocation` → `Identifier`; `Identifier.read(String)` returns `DataResult`.
- `SavedDataType(Identifier, Supplier, Codec, DataFixTypes)`; `MinecraftServer#getDataStorage()`.
- Permissions: `Commands.LEVEL_*` are `PermissionCheck`s; `PermissionLevel` enum; `ServerPlayer#permissions()`.
- GUI: `GuiGraphicsExtractor` (`text`, `fill`, `blitSprite(RenderPipelines.GUI_TEXTURED, …)`, `pose()` is a `Matrix3x2fStack`); the open screen is `Minecraft#gui.screen()`; F1 is `gui.hud.isHidden()`.
- `InputConstants.Type.KEYBOARD` (not `KEYSYM`); `KeyMapping.Category.register(Identifier)`.
- `Player#sendOverlayMessage(Component)` for the action bar.
- `GameTestHelper#makeMockServerPlayerInLevel()` is deprecated for removal in 26.3 (still works).
- Worldgen: configured features in `data/<ns>/worldgen/feature/`; loot table functions are `"modifier"`.
- `PushReaction.IMMOVEABLE` (no `BLOCK`); entity type constants in `EntityTypes`; `PoseStack#rotateDegrees(Axis, float)`.
- `CreativeModeTab.Output` is protected in vanilla: `:common` gets it through `META-INF/accesstransformer.cfg` (both loaders open it anyway).
- BER: `extractRenderState(be, state, partialTicks, cameraPos, crumbling)` + `submit(state, pose, collector, camera)`; items via `ItemModelResolver.updateForTopItem`, blocks via `BlockModelResolver.update`.
- Screens: `extractBackground` / `extractLabels`; the open screen is `Minecraft#gui.screen()`; `Minecraft#hasShiftDown()`.
- Block models: texture refs can be `{"sprite": ..., "force_translucent": true}`; elements support `light_emission`.
