# Tradery — спецификация (SPEC)

Источник правды для проекта. Основа — «Tradery — Техническое задание» (2026-09-30, @eliasnvx), исправленное по итогам ревью: устаревшие факты сверены с jar'ами MC 26.3 / Fabric API 0.161.0+26.3 / NeoForge 26.3.0.36-beta, противоречия разрешены, недостающие решения приняты. Все отступления от исходного ТЗ — в разделе [«Изменения относительно ТЗ»](#изменения-относительно-тз) и в `docs/decisions.md`.

## Обзор

Tradery — мультилоадерный мод (Fabric + NeoForge): виртуальная валюта с HUD-балансом, торговые автоматы и монетная руда как источник денег. Автор — eliasnvx, лицензия MIT.

**Цели проекта**

- Закрыть нишу «простой вендинг + виртуальный баланс» на актуальных версиях Minecraft
- Набрать скачивания на CurseForge/Modrinth как пассивный доход
- Дать другим модам публичный Economy API, чтобы Tradery стал стандартом экономики на NeoForge
- Позже — основа для платного Paper-плагина на BuiltByBit

**Целевая аудитория**

- Небольшие приватные и публичные модовые серверы (SMP)
- Авторы модпаков, которым нужна экономика «из коробки»
- Разработчики модов, которым нужно списывать/начислять деньги игрокам

## Позиционирование

Tradery — духовный наследник Vending Block (3.7M скачиваний, 823 модпака, умер на 1.12.2 в 2018). Современные ревайвы мелкие и сидят на одной версии, крупная экономика (Lightman's Currency) сложная и не вышла на 26.x.

| Мод | Версии / лоадеры | Чего нет |
| --- | --- | --- |
| Vending Block (оригинал) | 1.7.10–1.12.2, Forge | Заброшен с 2018 |
| Vending Block: Restocked | до 1.21.1, NeoForge | Нет валюты, Fabric, 26.x |
| Vending Block Revived | 1.7.10, Forge | Только 1.7.10 |
| Lightman's Currency | до 1.21.1 | Сложный; нет 26.x |
| Universal Shops (Patbox) | 26.3, Fabric, серверный | Нет HUD и блоков-автоматов; потребитель Common Economy API — с нашим мостом будет видеть балансы Tradery |
| EconomyCraft и аналоги | 1.21–26.x | Команды + сайдбар, нет HUD и вендинга |

На 2026-09-30 на Modrinth нет ни одного мода под 26.3 по запросу «vending».

**Отличия Tradery:** цена в вендинге предметом (классика) или валютой; HUD баланса; монетная руда как управляемый источник денег; публичный API и мост к Common Economy API; Fabric + NeoForge на актуальной версии.

**Название на площадках:** «Tradery — Vending Blocks & Economy». В описании прямо указать связь с Vending Block ради поиска.

## Scope MVP (v1.0)

**Входит**

1. Ядро экономики: аккаунты, валюта, атомарные транзакции, лог
2. Публичный Economy API с событиями
3. Мост к Common Economy API (Fabric)
4. HUD баланса со всплывающими изменениями
5. Вендинг-блок: цена предметом или валютой, офлайн-продажи, фасады, анимации витрины, уведомления, админские вендоры
6. Display-блок (витрина без продажи) и режим скупки в вендинге
7. Монетная руда (3 тира × камень/глубинный сланец), монеты-предметы, зачисление на баланс
8. Награды за мобов и действия через конфиг
9. Команды `/bal`, `/pay`, `/baltop`, `/eco`, `/tradery`
10. Интеграции: Jade, JEI, REI, Text Placeholder API (Fabric)
11. Локализация EN + RU

**Вне scope MVP**

- Мультивалютность (API её допускает, хранение тоже, но в MVP одна валюта)
- Банк, проценты, кредиты; аукцион и глобальный рынок; сетевые вендоры; динамические цены
- Автоматизация вендинга воронками/трубами (ни ввод, ни вывод)
- EMI и WTHIT — нет сборок под 26.3 на 2026-09-30; добавим, когда появятся (модуль интеграции изолирован)
- Дублирование событий в `NeoForge.EVENT_BUS`
- Paper/Bukkit-плагин
- Бэкпорт на 1.21.1 (v1.1) и Forge 1.20.1

### Версии Minecraft

Как у Femboy Mod и Bee Mastery: одна ветка на версию игры, у каждой своя копия кода; общая версия мода, файлы `<mod>+<mc>-<loader>`. Поведение, баланс, ключи языков и API одинаковые; отличаются только сигнатуры игры и форматы ресурсов.

| Ветка | Minecraft | Лоадеры | Java |
| --- | --- | --- | --- |
| `26.3-dev` (основная) | 26.3 | Fabric + NeoForge 26.3 | 25 |
| `1.21.1-dev` | 1.21.1 | Fabric (Loader 0.19.5, API 0.116.17+1.21.1) + NeoForge 21.1.256 | 21 |
| `1.20.1-dev` | 1.20.1 | Fabric (Loader 0.19.5, API 0.92.12+1.20.1) + Forge 47.4.26 | 17 |

**1.21.1** (ветка `1.21.1-dev`): игра обфусцирована — Fabric собирается Loom'ом с ремапом на Mojang-маппингах (`fabric-loom` 1.18.2), `:common` — через NeoForm `1.21.1-20240808.144430`. Отличия от 26.3:

- `ResourceLocation` вместо `Identifier`; `GuiGraphics` вместо `GuiGraphicsExtractor`; BER рисует сразу (без render state); блок-энтити — NBT `saveAdditional/loadAdditional` с кодеками через `RegistryOps`; `SavedData.Factory` в хранилище overworld (файлы `data/tradery_{accounts,history,stats}.dat`).
- Права: на Fabric — `me.lucko:fabric-permissions-api` 0.3.1 внутри jar (в Fabric API 1.21.1 модуля прав нет), на NeoForge — `PermissionAPI`; дефолты — уровни оператора.
- Монетка в тексте — глиф битмап-шрифта `tradery:coin` (object-компонентов в 1.21.1 нет).
- Ресурсы: `worldgen/configured_feature/`, loot `functions`/`conditions`, ингредиенты рецептов — объекты, модели предметов в `models/item/` (без `assets/tradery/items/`), прозрачность — `render_type` в модели (NeoForge) и `BlockRenderLayerMap` (Fabric); подсветка автомата — `neoforge_data.block_light` (только NeoForge: у Fabric нет поэлементной эмиссии).
- Метка мобов из спавнера — миксины `BaseSpawner`/`TrialSpawner` (в 1.21.1 нет причины спавна у `loadEntityRecursive`).
- Common Economy API 1.2.0 (1.2.1 вызывает методы 1.21.2+), версии интеграций — в `gradle.properties`.
- Клиентских GameTest у Fabric 1.21.1 нет: клиентские проверки и скриншоты — тест-мод NeoForge (`:neoforge:runClientTest`).
- Живой рынок (v1.1): `SavedData` хранятся как compound (караваны — под ключом `caravans`), профессии жителей — значения, а не holder'ы (`VillagerCompat`), «сегодня» считает `DayCounter` (часы 1.21.1 откатываются `/time set`), `StreamCodec.composite` до 6 полей — больше собирает `PortCodecs`. Датапаки грузятся `CodecJsonReloadListener` через `ResourceManagerHelper` (Fabric) и `AddReloadListenerEvent` (NeoForge). Шаблоны построек — палитра `Name`/`Properties`, DataVersion 3955; модификаторы в таблицах рынка — ключ `"function"`, разбор через `reloadableRegistries()`; путь шаблона из пула — аксессор `SinglePoolElement`; блоки с блок-энтити объявляют `RenderShape.MODEL`.

**1.20.1** (ветка `1.20.1-dev`, порт из 1.21.1): Fabric — Loom с ремапом на Mojang-маппингах; Forge 47 — ModDevGradle legacyforge (в рантайме SRG: reobf jar и refmap миксинов); `:api`/`:common` — MCP 1.20.1. Отличия от 1.21.1:

- Пакеты: своего `CustomPacketPayload`/`StreamCodec` нет — `network/TraderyPacket` (id канала + `write(FriendlyByteBuf)`); кодеки пакетов и данных меню — прослойка `network/codec` с теми же методами, что `StreamCodec`/`ByteBufCodecs` 1.20.5+ (размеры ограничены так же); Fabric — каналы Fabric API, Forge — один `SimpleChannel` `tradery:main`.
- Нет data components: предметы в NBT, сравнение — `isSameItemSameTags`; блоки — `Block#use`; сохранения — `SavedData#save(CompoundTag)` и `computeIfAbsent(load, create, name)`.
- GUI: атласа GUI-спрайтов нет — те же PNG рисуются как обычные текстуры.
- Права на Forge — `PermissionAPI`; метки поставленных блоков — capability чанка (Fabric — attachment).
- Common Economy API 1.1.1 (1.2.x требует 1.20.5+ и Java 21); MixinExtras нет на Forge 47 — миксины на чистом Mixin.
- Ресурсы: `pack_format` 15, папки во множественном числе (`tags/blocks`, `loot_tables`, `recipes`, `structures`), результат рецепта `{"item"}`, модификатор биомов `forge:add_features`, свечение — `forge_data`.
- Нет trial spawner'а (1.21): метку «из спавнера» ставит только обычный спавнер; из наград по умолчанию убраны отсутствующие в 1.20.1 мобы (`bogged`, `breeze`).
- Живой рынок (v1.1): у сделок жителей нет `ItemCost` — `village/ItemCost` поверх стеков `MerchantOffer`; спрайты окна торговли — UV из `villager2.png`; Java 17 (без pattern-switch и `List#getFirst`). DFU 6: `validate` → `flatXmap`, `listOf(min, max)` → `ConfigCodecs.sizeCheck`, все `optionalFieldOf` мягкие (строгое поле — `ConfigCodecs.strictOptionalField`), `byNameCodec` предметов читает неизвестный id как воздух (снимки магазинов проверяют id сами). Модификаторы таблиц рынка — лут-функции через Gson (`functions` 1.20.1, id — `minecraft:reference`), зачарованные книги — NBT `StoredEnchantments`, `enchant_randomly` — явный список чар стола зачарований (тегов чар нет); краски — свой тег `tradery:dyes`. Шаблоны построек — DataVersion 3465. Ракеты праздника — NBT `Fireworks`. Jade 11 — данные колокола в NBT. GameTest-мир перед прогоном удаляется (на Forge ещё и делается плоским: Forge гоняет тесты в мире из `server.properties`).

## Архитектура

Четыре Gradle-модуля (папки `api/`, `common/`, `fabric/`, `neoforge/`; артефакты `tradery-api`, `tradery-fabric`, `tradery-neoforge`):

- `:api` — публичный контракт. Зависит только от ванильного Minecraft. Публикуется в Maven отдельно.
- `:common` — вся логика. Реализует API. Не импортирует `net.fabricmc.*` / `net.neoforged.*`.
- `:fabric`, `:neoforge` — тонкие обёртки: компилируют исходники `:api` + `:common` вместе со своими в один jar.

Платформенные различия спрятаны за интерфейсом `Platform` в common; лоадер устанавливает реализацию первым делом в своём инициализаторе. Зависимости идут только вниз: платформы знают про common, common реализует API, внешние моды видят только API.

**Пакеты** — корень `dev.eliasnvx.tradery`

```
api/       dev.eliasnvx.tradery.api          TraderyEconomy, Account, AccountId, Currency, Reason, TransactionResult
           .api.event                          Event<T>, EventPriority, все события
common/    .economy   .vending   .ore   .rewards   .command
           .client    .network   .config   .compat   .platform   .registry   .gametest
fabric/    .fabric    (+ .fabric.compat.commoneconomy, .fabric.compat.placeholders — Fabric-only моды)
neoforge/  .neoforge
```

Правило интеграций: код интеграции для модов, доступных на обоих лоадерах, живёт в `common/.../compat/<modid>`; для Fabric-only модов — в `fabric/.../compat/<modid>`. Подключение только после проверки `isModLoaded`, отсутствие мода никогда не крашит игру.

## Economy API

Артефакт `dev.eliasnvx:tradery-api:<api_version>+<mc>` (без зависимостей от реализации), проектируется до вендинга. Деньги — `long` в минимальных единицах (при `decimals: 2` — сотые), никаких `double`.

**Основные типы** (`Identifier` — в 26.x это бывший `ResourceLocation`)

```java
public interface TraderyEconomy {
    static TraderyEconomy get();                  // точка входа; IllegalStateException, если сервер не запущен
    Currency defaultCurrency();
    Optional<Currency> currency(Identifier id);
    Account account(UUID player);                 // аккаунт игрока, создаётся лениво
    Optional<Account> account(AccountId id);      // любой существующий аккаунт
    Account systemAccount(Identifier id);         // системный аккаунт мода, создаётся лениво
    Account serverAccount();                      // tradery:server — бесконечный (см. ниже)
    TransactionResult transfer(Account from, Account to, long amount, Reason reason);
    TransactionResult transfer(Account from, Account to, long amount, long fee, Reason reason); // fee сжигается
    TransactionResult deposit(Account to, long amount, Reason reason);    // эмиссия
    TransactionResult withdraw(Account from, long amount, Reason reason); // сжигание
}

public interface Currency {
    Identifier id();
    int decimals();                  // 2 → 1.50
    Component format(long amount);   // "1 250.00 ₮"
    String formatPlain(long amount);
    Component name();
    String symbol();
}

public interface Account {
    AccountId id();
    long balance(Currency c);
    boolean canAfford(Currency c, long amount);
    boolean isInfinite();            // tradery:server и другие бесконечные системные аккаунты
    boolean isLocked();
}

public sealed interface AccountId { record Player(UUID uuid); record System(Identifier id); }

public sealed interface TransactionResult {
    record Success(UUID txId, long amount, long fee, long balanceFrom, long balanceTo) implements TransactionResult {}
    record Failure(FailReason reason, @Nullable Component message) implements TransactionResult {}
}
// balanceFrom / balanceTo = TransactionResult.NO_BALANCE (-1) для отсутствующей стороны (deposit / withdraw)
// и для бесконечного аккаунта.

enum FailReason { INSUFFICIENT_FUNDS, CANCELLED, INVALID_AMOUNT, ACCOUNT_LOCKED, LIMIT_EXCEEDED }

public record Reason(Identifier type, @Nullable String note) {}
```

**Бесконечный аккаунт** `tradery:server`: перевод с него — эмиссия, на него — сжигание. Владелец админских вендоров.

**Идентификаторы причин** — единый формат `tradery:<категория>/<действие>`:

| Reason | Когда |
| --- | --- |
| `tradery:pay` | `/pay` |
| `tradery:vending/sale` | Покупка в автомате (покупатель → владелец) |
| `tradery:vending/buyback` | Скупка (владелец → продавец) |
| `tradery:ore/mined` | Добыча монетной руды с зачислением на баланс |
| `tradery:coin/deposit` | Монеты → баланс (подбор, ПКМ) |
| `tradery:coin/withdraw` | Баланс → монеты (`/tradery withdraw`) |
| `tradery:reward/kill`, `/mine`, `/craft`, `/fish`, `/advancement` | Награды |
| `tradery:admin/give`, `/take`, `/set` | `/eco` |
| `tradery:account/starting_balance` | Стартовый баланс нового аккаунта |
| `<modid>:<что угодно>` | Другие моды |

**События экономики**

| Событие | Когда | Отмена | Изменение |
| --- | --- | --- | --- |
| `TransactionEvent.Pre` | До списания/зачисления | Да, с текстом | Сумма и комиссия (налоги, бонусы) |
| `TransactionEvent.Post` | После успешной транзакции | Нет | — |
| `BalanceChangedEvent` | Любое изменение баланса аккаунта | Нет | — |
| `AccountCreatedEvent` | Первое обращение к аккаунту | Нет | Стартовый баланс |

**События механик**

| Событие | Когда | Отмена | Изменение |
| --- | --- | --- | --- |
| `VendingPurchaseEvent.Pre` | Перед сделкой (покупка или скупка) | Да, с текстом | Цена, количество сделок |
| `VendingPurchaseEvent.Post` | После успешной сделки | Нет | — |
| `VendingPlacedEvent` | Игрок ставит автомат | Да, с текстом | — |
| `VendingConfiguredEvent` | Владелец сохраняет настройки | Да, с текстом | Цену |
| `CoinOreMinedEvent` | Добыта монетная руда, до начисления/дропа | Да | Сумму, режим (баланс / предметы) |
| `CoinPickedUpEvent` | Игрок подбирает монету с земли | Да | Сумму зачисления |
| `RewardGrantedEvent` | Перед выдачей награды | Да | Сумму |

```java
// налог 5% на продажи в регионе «market»
VendingPurchaseEvent.Pre.EVENT.register(e -> {
    if (Regions.at(e.pos()).is("market")) e.setPrice(e.price() * 105 / 100);
});
// двойные деньги с руды по выходным
CoinOreMinedEvent.EVENT.register(e -> { if (isWeekend()) e.setAmount(e.amount() * 2); });
```

События — свои платформонезависимые шины `Event<T>` с приоритетами (`HIGHEST … LOWEST`) в `:api`; аддон пишется один раз под оба лоадера. Исключение в слушателе логируется, остальные слушатели продолжают работать. Отменённое событие не доходит до следующих слушателей, кроме зарегистрированных с `receiveCancelled = true`.

**Контракты**

- Все методы вызываются только на серверном потоке; вызов с другого потока — `IllegalStateException`
- Транзакция атомарна: либо обе стороны изменились, либо ни одна
- Сумма ≤ 0 или комиссия вне `[0, amount]` — `INVALID_AMOUNT`
- Переполнение `long` или превышение `maxBalance` у получателя — `LIMIT_EXCEEDED`, баланс не меняется
- Заблокированный аккаунт (`/eco lock`) — `ACCOUNT_LOCKED`
- API версионируется по semver отдельно от мода; ломающие изменения только в мажоре

## Хранение и синхронизация

Сервер — единственный источник правды. Балансы и прочее — в серверном `SavedData` (`server.getDataStorage()`, `SavedDataType(Identifier, Supplier, Codec, DataFixTypes)`), лог — в файлы, клиент получает только своё. Внешней БД нет.

| Данные | Где | Формат |
| --- | --- | --- |
| Аккаунты: балансы, флаги, последнее имя игрока, `decimals` мира | `SavedData` `tradery:accounts` | `Codec`, `setDirty()` после транзакции |
| Последние транзакции игрока (20 шт., для `/tradery history`) | `SavedData` `tradery:history` | `Codec`, кольцевой буфер на аккаунт |
| Статистика (эмиссия, сжигание, наличные в обороте, по дням) + дневные счётчики лимитов | `SavedData` `tradery:stats` | `Codec`; сутки — по UTC-дате сервера |
| Непрочитанные уведомления (офлайн-продажи) | `SavedData` `tradery:notifications` | Очередь на UUID, лимит 100 + агрегат сводки (не теряется при переполнении) |
| Индекс автоматов (позиция, измерение, владелец) | `SavedData` `tradery:vendors` | Для `/tradery vendors` и `vending.maxPerPlayer` |
| Лог транзакций | `<world>/tradery/logs/YYYY-MM-DD.log` | JSON Lines, асинхронная запись, ротация `log.retentionDays` |
| Состояние автомата | BlockEntity | Склад, цена, владелец, настройки (`ValueInput`/`ValueOutput`) |
| Флаг «поставлено игроком» | Data Attachment чанка (Fabric Data Attachment API / NeoForge attachments) | Набор позиций; только для блоков из списка наград `mine` |
| Серверный конфиг | `config/tradery/server.json5` | JSON5 |
| Награды | `config/tradery/rewards.json5` | JSON5 |
| Клиентский конфиг | `config/tradery/client.json5` | JSON5 |

**Сохранность и краши.** `setDirty()` пишет на диск на автосейве и при остановке. Но Minecraft сохраняет изменённый чанк сам примерно через 10 с после изменения, а данные сервера (балансы) и игроков (инвентари) — только на автосейве. Поэтому, когда сохраняется чанк автомата, с которым торговали после его прошлого сохранения, в том же тике сохраняются экономика и данные этих игроков (`TradePersistence`, миксин на `ChunkMap#save`). Итог после `kill -9`: склад, деньги и инвентари участников сделки всегда из одного момента — без дюпа и без потери (проверено `tools/crash-test.sh`; без этого склад оказывался новее денег). Лог — аудит, а не источник правды: после краша в нём могут быть откаченные транзакции; каждый старт сервера пишет в лог строку-маркер `server_start`.

**Единицы в конфиге.** Денежные значения в конфигах — в основных единицах валюты (`100`, `0.5`), переводятся в минимальные по `decimals` (лишние знаки отбрасываются с предупреждением в логе). `decimals` фиксируется за миром при первом запуске (в `tradery:accounts`); смена в конфиге на существующем мире игнорируется с предупреждением. Символ, имя и разделитель — только отображение, берутся из конфига.

**Сетевые пакеты** (custom payloads, `StreamCodec` в common, строки и коллекции ограничены по размеру)

| Пакет | Направление | Содержимое | Когда |
| --- | --- | --- | --- |
| `S2C CurrencyInfo` | сервер → клиент | id, имя, символ, decimals, разделитель | Вход (до `BalanceSync`), `/tradery reload` |
| `S2C BalanceSync` | сервер → клиент | currency id, баланс | Вход, смена измерения, респаун |
| `S2C BalanceDelta` | сервер → клиент | дельта, новый баланс, reason type | Каждое изменение баланса игрока |
| `S2C Notification` | сервер → клиент | тип, ключ перевода, аргументы | Продажа, пустой автомат, нет места, сводка |
| `S2C HudToggle` | сервер → клиент | — | `/tradery hud` |
| `C2S VendingConfigure` | клиент → сервер | pos, настройки | Сохранение в GUI владельца |
| `C2S VendingBuy` | клиент → сервер | pos, количество сделок | Клик «Купить» |
| `C2S VendingQuickTrade` | клиент → сервер | pos, купить/продать | Shift+ПКМ / Shift+ЛКМ по автомату; при удержании — не чаще раза в 4 тика |

Каналы опциональные: сервер не шлёт пакеты клиенту без Tradery (проверка канала), клиент без сервера с Tradery просто не показывает HUD.

**Правила для C2S**

- Проверяется: дистанция ≤ 8 блоков, чанк загружен, открыт меню именно этого автомата, права владельца (для настроек)
- Rate limit `VendingBuy`: не больше 10 в секунду на игрока, лишнее отбрасывается
- Клиент ничего не считает — только отображает то, что прислал сервер

## Вендинг-блок

Один блок — одна сделка: «N штук товара за цену». Цена — предметом (классика) или валютой. Продажи идут, пока чанк загружен; владелец может быть офлайн.

| ID | Что это | Крафт |
| --- | --- | --- |
| `tradery:vending_block` | Торговый автомат, 1 сделка | Сундук + стекло + золото |
| `tradery:display_block` | Витрина без продажи | Стекло + плита |
| `tradery:vendor_key` | Админский ключ, открывает админ-экран | Только креатив / команда |

**Настройки сделки (владелец)**

- Товар: предмет-образец + количество за сделку (1–64)
- Режим цены: `ITEM` (предмет + кол-во) или `CURRENCY` (сумма)
- Сравнение предметов — строгое: предмет + все компоненты (`ItemStack.isSameItemSameComponents`), и для товара, и для цены
- Склад товара: 27 слотов; выручка предметами — 9 слотов
- В режиме `CURRENCY` выручка сразу идёт на баланс владельца минус комиссия `vending.feePercent` (сжигается)
- Пресеты количества при покупке: 1 / 8 / макс. доступное
- Предметы из `vending.itemBlacklist` нельзя выставить товаром или ценой

**Режим скупки** (галка в GUI, только `CURRENCY`): автомат покупает у игроков предмет-образец за валюту с баланса владельца, пока хватает денег и места на складе. Купленное ложится на склад.

**Сценарий покупки**

1. ПКМ — GUI покупателя: товар, цена, остаток, кнопки «Купить ×1 / ×8 / ×макс»
2. Сервер проверяет: товар есть, покупателю хватает денег/предметов, в инвентаре есть место, у владельца есть место под выручку (`ITEM`)
3. Одна атомарная операция: списание → зачисление владельцу → выдача товара
4. Любая проверка упала — ничего не меняется, игрок видит причину

**Быстрая сделка без окна** (как в оригинальном Vending Block)

- Shift + ПКМ по продающему автомату — купить одну сделку; Shift + ЛКМ по скупающему — продать одну сделку. Зажал — сделки идут дальше, примерно 5 в секунду (клиент шлёт запрос не чаще раза в 4 тика, на сервере действует тот же rate limit 10/с)
- Не та кнопка — подсказка, какие клавиши нужны; ванильное действие (поставить блок из руки, копать) при этом не выполняется
- Обратная связь: звук у автомата (сделка / отказ) и строка над хотбаром с суммой серии: «Куплено 20 × Хлеб за 🪙12.50»
- Владелец своим автоматом так не торгует: у него Shift + клик работает как в ванилле (владелец может сломать свой автомат)
- Товар сразу в инвентарь (место проверяется до оплаты), как и в окне

**Подсказка при наведении**

- Вверху по центру экрана, пока прицел на автомате: владелец, товар и цена с иконками, строка с клавишами («Shift + ПКМ — купить · ПКМ — окно») или причина, почему сделки нет (не настроен, товар закончился)
- С зажатым Shift — полные подсказки предметов (зачарования, эффекты зелий)
- Если стоит Jade, подсказка по умолчанию выключена (Jade показывает то же через плагин Tradery, включая строку с клавишами); режим `AUTO`/`ON`/`OFF` и отступ — в `client.json5`

**Внешний вид**

- Фасад: основание принимает модель любого полного блока (клик блоком в GUI владельца или drag из JEI/REI). Блэклист в конфиге
- Анимации товара в витрине: `STATIC`, `SPIN`, `BOB`, `SPIN_BOB`, `NONE`. Дефолт — сервер, игрок может переопределить у себя
- Подсветка по состоянию: зелёная — в наличии, серая — пусто

**Уведомления владельцу** (каждое отключается в клиентском конфиге)

- Продажа: «Продано 16 × Хлеб за 40 ₮ (Steve)»
- Автомат пуст
- Нет места для выручки (режим `ITEM`) — автомат останавливается
- Офлайн-продажи копятся и выдаются сводкой при входе: «Пока вас не было: 12 продаж, +480 ₮»

**Админский экран** (через `vendor_key`, право `tradery.admin.vendors`): сменить владельца (в т.ч. на `tradery:server`), бесконечный склад, сжигать оплату вместо зачисления, вне комиссии.

**Защита**

- Сломать автомат может только владелец или оп; взрывы, поршни и гравитация не действуют
- Автоматизации нет: блок не реализует `Container`, не отдаёт capability/Storage — воронки и трубы не могут ни положить, ни забрать
- При поломке владельцем содержимое склада и выручки выпадает; открытые GUI закрываются

## HUD баланса

Баланс всегда виден (дефолт — правый нижний угол, ниже зоны субтитров); каждое изменение показывается всплывающей строкой `+120` / `-40`, которая уезжает вверх и гаснет за 2 секунды.

- Позиция: 4 угла + смещение X/Y; масштаб 0.5–2.0
- Формат: полный (`1 250.00`) или короткий (`1.2K`); разделитель — из `CurrencyInfo`. Символ валюты в HUD, на экранах вендинга и в подсказке Jade не пишется: его заменяет иконка монеты (в чате и в командах символ остаётся)
- Иконка монеты слева от числа
- Скрывается при F1, при открытом экране и если сервер без Tradery
- Анимация прокрутки числа (~300 мс), отключаемая
- Всплывашки: зелёные — приход, красные — расход, не больше 3 одновременно
- Клавиша (по умолчанию не назначена) и `/tradery hud` — скрыть/показать, состояние сохраняется в клиентском конфиге
- Регистрация: Fabric `HudElementRegistry`, NeoForge `RegisterGuiLayersEvent`; общий рендер в common

## Монетная руда

Главный источник новых денег. По умолчанию добыча сразу зачисляется на баланс игрока; монеты-предметы — конфигом. Частота, номиналы и глубина настраиваются датапаком и конфигом.

**Тиры** (дефолты; генерация — датапак, номиналы — конфиг)

| Руда | Высота Y | Жил на чанк | Размер жилы | Дроп | Номинал монеты |
| --- | --- | --- | --- | --- | --- |
| Медная монетная | 0…96 | 6 | 4–6 | 1–3 медные | 1 ₮ |
| Серебряная монетная | −32…32 | 3 | 3–5 | 1–2 серебряные | 10 ₮ |
| Золотая монетная | −64…−16 | 1 | 2–4 | 1 золотая | 100 ₮ |

Каждая руда — в вариантах камень и глубинный сланец. Незер-вариант — вне MVP.

**Монеты и начисление**

- Loot table руды — источник правды по количеству монет (датапак может менять дроп и включать Fortune через `apply_bonus` в `"modifier"`; в 1.21.1 — в `"functions"`)
- `ore.directToBalance: true` (дефолт): когда руду добывает игрок в выживании подходящим инструментом, монеты из loot table не выпадают, их сумма сразу зачисляется (`tradery:ore/mined`). В креативе — ничего
- Руду ломает не игрок (бур Create, взрыв) — выпадают монеты-предметы. В режиме `directToBalance` монета, подобранная игроком с земли, сразу зачисляется и исчезает (работает и с полным инвентарём). Монеты, собранные воронкой или лежащие в сундуке, остаются предметами
- Режим предметов (`directToBalance: false`): `tradery:copper_coin`, `silver_coin`, `gold_coin`, стак 64; ПКМ — зачислить стак, Shift+ПКМ — все монеты из инвентаря
- `/tradery withdraw <сумма>` — снять монетами (сумма должна раскладываться на номиналы); работает в обоих режимах
- Достигнут `ore.dailyCap` — руда ничего не даёт (ни баланса, ни монет), игрок видит сообщение

**Генерация**

- `data/tradery/worldgen/feature/*.json` (в 26.3 это бывший `configured_feature`; в 1.21.1 — `worldgen/configured_feature/`) + `worldgen/placed_feature/*.json`, ванильный `minecraft:ore`
- В биомы: NeoForge — `data/tradery/neoforge/biome_modifier/*.json`, Fabric — `BiomeModifications` по тегу биомов `tradery:has_coin_ore`
- Сервер меняет частоту и высоту датапаком (переопределяет `placed_feature`)
- `ore.enabled: false` — руда не генерируется

**Защита от инфляции и эксплойтов**

- Руда не входит в `c:ores` и аналоги, рецептов обработки нет — дробилки Create/Mekanism не умножают монеты
- Fortune по умолчанию не действует (нет `apply_bonus`), сервер включает датапаком
- Silk Touch даёт блок руды — деньги начислятся при следующей добыче, это не дюп
- `ore.dailyCap` — лимит дохода с руды в сутки на игрока (0 = без лимита)
- `ore.inflationDamping`: множитель дропа `clamp(targetSupply / денежная масса, minFactor, 1)`, дробная часть — вероятностным округлением

**Стоки денег:** комиссия вендинга (`vending.feePercent`, дефолт 2%), налог `/pay` (`pay.taxPercent`, дефолт 0%), админские вендоры со сжиганием.

## Награды за мобов и действия

Второй источник денег — `config/tradery/rewards.json5`. По умолчанию включены только мобы.

| Тип | Ключ | Пример | Дефолт |
| --- | --- | --- | --- |
| Убийство моба | `kill` | `minecraft:zombie` → 1–3 ₮ | Вкл, враждебные мобы |
| Добыча блока | `mine` | `minecraft:diamond_ore` → 5 ₮ | Выкл |
| Крафт | `craft` | `minecraft:bread` → 0.1 ₮ | Выкл |
| Рыбалка | `fish` | любой улов → 1 ₮ | Выкл |
| Продвижение | `advancement` | `minecraft:story/enter_the_nether` → 50 ₮ | Выкл |

```json5
{
  kill: { enabled: true, rewards: {
    "minecraft:zombie":   { min: 1, max: 3, chance: 1.0 },
    "minecraft:creeper":  { min: 2, max: 4 },            // chance по умолчанию 1, max по умолчанию = min
    "#minecraft:raiders": { min: 5, max: 10 },           // теги поддерживаются, "*" — что угодно
  } },
  mine: { enabled: false, rewards: { "minecraft:diamond_ore": { min: 5 } } },
  rules: {
    ignoreSpawnerMobs: true,   // мобы из спавнеров и trial spawner не платят
    ignoreFakePlayers: true,   // Deployer, авто-мечи
    dailyCap: 1000,            // потолок в сутки на игрока, 0 = нет
    diminishing: { windowSec: 60, after: 20, factor: 0.5 }
  }
}
```

- Награда начисляется через API с `Reason` = `tradery:reward/<тип>` — видна в логе и HUD
- Блоки, поставленные игроком, не дают награду `mine` (флаг в Data Attachment чанка). Ограничение: блок, сдвинутый поршнем, теряет флаг — поэтому `mine` выключена по умолчанию
- `ignoreSpawnerMobs`: метка на сущности по причине спавна `EntitySpawnReason.SPAWNER` / `TRIAL_SPAWNER` (в 1.21.1 — миксины `BaseSpawner`/`TrialSpawner`), проверяется при смерти
- `craft`: предупреждение в конфиге — обратимые рецепты (9 слитков ↔ блок) превращаются в бесконечные деньги; награда выдаётся только за перечисленные предметы

## Живой рынок (v1.1)

Жители деревень становятся покупателями автоматов игроков, в деревнях появляются рынки, где валюту можно потратить, а окно торговли жителя работает в валюте вместо изумрудов. Изумруды остаются предметом: их меняют на валюту у менялы на рынке. Решения автора 2026-10-18; продажа жителями сырья на автоматы скупки — не в 1.1.

**Покупатели-жители**

- Покупают настоящие жители деревни, новых не спавним. Подходит взрослый житель, который не спит, не паникует, не торгует с игроком и сейчас в дневной активности (`WORK`, `MEET`, `IDLE`, `PLAY`). С `villagers.requireHomeAndJob` (дефолт) — только жители с кроватью (`HOME`) и рабочим местом (`JOB_SITE`): житель в клетке-ферме до прилавка не дойдёт и не считается.
- Автомат должен принадлежать игроку, продавать за валюту (`CURRENCY`, не скупка), иметь товар и включённую галку «Жители могут покупать» (GUI владельца, дефолт — вкл). Серверные автоматы жители не обслуживают.
- Блок-энтити автоматов не тикают: раз в `villagers.checkIntervalTicks` тиков сервер проходит по загруженным автоматам из индекса автоматов и с шансом зовёт одного подходящего жителя в радиусе `villagers.visitRadius`. Шанс растёт с репутацией владельца в деревне.
- Житель идёт к клетке перед автоматом (`WALK_TARGET`), смотрит на товар `villagers.browseTicks` тиков и решает. Не дошёл за `villagers.walkTimeoutTicks` — поход отменяется. После визита у жителя пауза `villagers.customerCooldownTicks`.
- Покупка — та же атомарная сделка, что у игрока: товар уходит со склада (житель уносит его, предметы исчезают), владелец получает цену минус `vending.feePercent`. Уведомление владельцу: «Фермер купил 4 × Хлеб за 🪙10.00»; офлайн-сводка считает и продажи жителям. Частицы и звук жителя у прилавка.
- Работает только в загруженных чанках; задним числом продажи не досчитываются.

**Деньги жителей**

- У жителя кошелёк. Раз в игровые сутки (лениво, при следующем визите) он пополняется на дневную ставку по уровню профессии: `villagers.wages` = новичок 3, ученик 5, подмастерье 8, эксперт 12, мастер 18 (основные единицы); без профессии и бездельник — `villagers.wages.none` 1. Кошелёк не больше `villagers.walletDays` дневных ставок. Прокачал жителя торговлей — получил богатого покупателя.
- Деньги, которые игроки платят жителю в окне торговли, тоже ложатся в кошелёк, без потолка `walletDays`: заработанное житель тратит у прилавков и отдаёт игрокам за их товар.
- Деньги покупки создаются (от `tradery:server`) — это источник денег, как руда. Ограничения: кошелёк, `villagers.dailyCapPerVillage` (сколько в сутки может потратить одна деревня), множитель `ore.inflationDamping` (общий для руды и жителей). `Reason` — `tradery:villager/purchase`.
- Кошельки и состояние деревень — серверные saved data (`tradery_villagers`), не в сущностях: одинаково на всех лоадерах. Запись умершего жителя удаляется.

**Что жителю нужно и почём**

- Нужды — датапак `data/<ns>/tradery/villager_wants/*.json`: профессия (или `any`) → предметы/теги с весами. Дефолт: еду покупают все; фермер — костную муку и мотыги, рыбак — удочки и нитки, библиотекарь — бумагу и книги и т. д.
- Честная цена — датапак `data/<ns>/tradery/prices/*.json`: предмет/тег → цена за штуку. Предмет без честной цены жители не покупают.
- Цена за штуку `r` = цена автомата / честная. `r ≤ 1` — покупает (с учётом спроса); `1 < r < villagers.maxPriceRatio` (1.5) — шанс падает линейно до нуля; дороже — не покупает.
- Спрос деревни на предмет — от 0 до 1: каждая проданная сделка снижает его на `villagers.demandDropPerLot`, за сутки он восстанавливается на `villagers.demandRecoveryPerDay`. Деревня — по колоколу (`MEETING_POINT` жителя), без колокола — по региону 64×64.
- За визит житель берёт до `villagers.maxLotsPerVisit` сделок, сколько позволяют кошелёк, склад и спрос.

**Репутация** — ванильные слухи жителя (`GossipContainer`) о владельце: честная цена (`r ≤ 1`) добавляет `TRADING`, завышенная (`r ≥ villagers.gougingRatio`) — `MINOR_NEGATIVE`. Репутация владельца в деревне увеличивает шанс визита (×0.5…×2) и, как в ванилле, даёт скидки в обычной торговле.

**Торговля с жителями за валюту** (`villagerTrading`)

- ПКМ по жителю открывает окно Tradery вместо ванильного. Сделки те же: профессия, уровень, лимит использований, спрос, скидки за репутацию и «Героя деревни». Каждый изумруд в сделке становится суммой `villagerTrading.emeraldValue` (дефолт 3 — столько стоит изумруд у менялы).
- Изумруды в цене списываются с баланса игрока и ложатся в кошелёк жителя. Остальные предметы цены берутся из инвентаря (как ванильная автоподстановка; сначала стаки без имени и чар). Результат идёт в инвентарь, что не влезло — падает у ног.
- Изумруды в результате житель платит из кошелька на баланс игрока. Не хватает — сделка не проходит: «У жителя кончились деньги, приходи завтра» (кошелёк пополняется ставкой раз в сутки).
- Одна сделка — одна транзакция экономики: оплата уходит на `tradery:server` (из оборота), выплата создаётся от `tradery:server`. `Reason` — `tradery:villager/trade`. Сначала деньги (могут не пройти: баланс, потолок, событие API), потом предметы — проверены заранее, так что сделка не проходит наполовину.
- Опыт и уровень жителя, слухи `TRADING`, статистика и триггер достижения `minecraft:villager_trade` — ванильные (`notifyTrade`).
- Окно: слева список сделок (цена в монетах, скидка — старая цена зачёркнута), справа выбранная сделка, «у тебя есть», баланс, кошелёк жителя, полоса опыта, кнопки «Обменять» и «Обменять всё» (пока хватает денег, предметов и лимита). Предметных слотов нет. После сделки сервер шлёт окну свежие сделки, кошелёк и опыт.
- Странствующий торговец не меняется: кошелька у него нет, торгует за изумруды. `villagerTrading.enabled: false` — ванильное окно и изумруды.
- Сохранение: деньги (saved data) и инвентарь (данные игрока) пишутся на диск вместе — игроки со сделками у жителей сохраняются, когда `TradePersistence` сохраняет данные экономики, и при выходе игрока данные экономики сохраняются в тот же тик.

**Рынок деревни**

- В пулы домов пяти типов деревень (равнины, пустыня, саванна, тайга, снежная) добавляется прилавок рынка (вес `market.weight`; `market.enabled: false` — не добавляется). На прилавке 2–3 серверных автомата: бесконечный склад, оплата сжигается (сток денег).
- Товар выбирается при генерации процессором структуры `tradery:market_stock` из датапака `data/<ns>/tradery/market/<тип деревни>.json` (предложения с весами и диапазоном цен): зачарованные книги, бирки, сёдла, карты, редкие семена и т. п.
- Меняла: пара автоматов «изумруд за валюту» и скупка «валюта за изумруд» (`market.emeraldSellPrice`, `market.emeraldBuyPrice`, покупка дешевле продажи).
- Сломать прилавки рынка может только оп (серверный владелец).

```json5
// server.json5, новые секции
villagers: { enabled: true, requireHomeAndJob: true, visitRadius: 32, checkIntervalTicks: 100, visitChance: 0.25,
             browseTicks: 60, walkTimeoutTicks: 600, customerCooldownTicks: 6000, maxLotsPerVisit: 3,
             wages: { none: 1, novice: 3, apprentice: 5, journeyman: 8, expert: 12, master: 18 }, walletDays: 3,
             dailyCapPerVillage: 200, maxPriceRatio: 1.5, gougingRatio: 1.25,
             demandDropPerLot: 0.05, demandRecoveryPerDay: 0.25 },

```

## Деревня-экономика (v1.1)

Деревня — не набор жителей, а экономика: у неё есть казна, процветание, специализация, заказы, рынок и враги. Игрок растит её торговлей и вложениями. Всё оплачивается настоящими деньгами Tradery из кошельков жителей и казны; награды из воздуха (изумруды, лут) — нет. Решение автора 2026-10-20: всё это входит в 1.1, затем порты.

Отличие от модов про деревни (Sovereign, Pueblo Vivo, Village Bounties, Villages Plus, Mercantile): у них награды и рост не связаны с деньгами; здесь каждый заказ, поставка, налог и вложение — движение денег, видимое в экономике (`/eco stats`).

**Деревня и перепись**

- Деревня = колокол (POI `meeting`). Ключ — измерение и позиция колокола. Жители относятся к деревне по памяти `MEETING_POINT`. Состояние деревни — в saved data `tradery_villagers` (расширение того, что уже хранит спрос и траты), одинаково на всех лоадерах.
- Перепись раз в `villages.censusIntervalTicks` (600) для деревень с загруженным колоколом: население (взрослые), занятые (с профессией), профессии по количеству, тип деревни (тип большинства жителей: plains, desert, savanna, taiga, snow, jungle, swamp). Деревня «известна» после первой переписи; не виденная `FORGET_AFTER_DAYS` дней забывается.
- Без загруженных чанков ничего не симулируется задним числом; суточные начисления (казна, распад процветания) — лениво, при следующем касании, по числу прошедших игровых дней.

**Процветание**

- Очки процветания: деньги, потраченные жителями у лавок игроков (1 очко за 1.00 основной единицы), оборот окна торговли жителя (×0.5), выполненные заказы (награда ×1), поставки жителей на скупку (×0.5), вложения (стоимость ×0.5). Раз в сутки — минус `villages.prosperityDecayPerDay` (5%).
- Уровни (`villages.levels.thresholds`, пороги очков): 1 «Хутор» 0, 2 «Село» 300, 3 «Городок» 1500, 4 «Торговый город» 5000. Уровень показывается на доске и в подсказке над колоколом.
- По уровню (массивы в конфиге, индекс = уровень): ставки жителей ×1 / ×1.25 / ×1.5 / ×2; заказов на доске 3 / 4 / 5 / 6; рыночный день раз в 7 / 5 / 4 / 3 дня; лимит трат деревни в сутки ×1 / ×1.5 / ×2 / ×3; караваны — с уровня 3.

**Казна**

- Раз в сутки: `villages.treasuryPerVillager` (1.00) × население × множитель уровня; не больше `villages.treasuryDays` (7) таких сумм. Сверх этого, без потолка: аренда мест, `villages.tradeTaxPercent` (10%) денег, которые игроки платят жителям в окне торговли.
- Из казны платятся награды заказов. Казна — счётчик, как кошельки: выплата создаётся от `tradery:server`, оплата игрока сжигается. Пустая казна — меньше и скромнее заказы.
- Пожертвование (решение автора 2026-10-23): на вкладке «Деревня» первая строка списка проектов — «Пожертвование в казну»: игрок вводит сумму и отдаёт её в казну сверх потолка (`Reason` — `tradery:village/donation`, деньги сжигаются); процветание и благодарность жителей — как за проект той же стоимости. Проверки как у кнопок доски: открытое окно, досягаемость, лимит частоты сделок.
- История: деревня хранит последние 7 дней движения казны (`history`: день, пришло, ушло) — суточный доход, налог, аренда, пожертвования и вернувшиеся деньги (истёкшие заказы, кошелёк каравана) как приход; резерв заказов, кошелёк каравана и потери рейда как расход. Доска показывает их на вкладке «Деревня» столбиками (зелёный — приход, красный — расход) с подсказкой по дням и итогом за неделю.

**Доска деревни** (`tradery:village_board`)

- Блок: крафтится (3 доски, 2 бумаги, табличка), генерируется на прилавках рынка. Привязывается к ближайшему колоколу в радиусе `villages.boardRadius` (48); колокола нет — «Здесь нет деревни». Сломать доску на рынке может только оп; поставленную игроком — кто угодно (это просто вход в деревню).
- Окно с вкладками: «Заказы», «Деревня» (население, занятые, профессии, казна и её неделя, процветание и уровень, твоя репутация, пожертвование и проекты), «Рынок» (что здесь дёшево и дорого, рыночный день, торговое место, караваны).
- Над колоколом при взгляде — подсказка: название уровня, процветание, «рыночный день сегодня/через N дней».
- При входе в деревню (радиус `villages.boardRadius` от её колокола) и при смене её уровня на экране на несколько секунд проявляется название деревни и уровень (сервер проверяет игроков раз в 2 секунды). Клиентский конфиг `villageTitle`: `enabled`, `offsetY` (от верха экрана; по центру, чтобы не задевать миникарты в углах), `scale`.

**Заказы**

- На рассвете (лениво при открытии доски) деревня вывешивает заказы — столько, сколько даёт уровень. Предмет — из нужд профессий деревни (`villager_wants`, по переписи) и из дефицита деревни (специализация); количество 8–64 по цене. Награда = честная цена × количество × `orders.rewardMarkup` (1.3) × региональный множитель; заказ вывешивается, только если казна его покрывает (сумма резервируется).
- Сдача через окно доски: предметы из инвентаря (только «чистые», без имени и чар), частично или полностью; награда пропорционально, из казны на баланс. `Reason` — `tradery:village/order`. Заказ общий для всех игроков; срок — `orders.lifetimeDays` (2) дня.
- Каждая сдача — репутация `TRADING` у жителей деревни рядом и очки процветания.
- После рейда — «заказы на восстановление» (доски, стекло, булыжник, факелы), награда ×`threats.restorationMarkup` (1.5), 3 дня.

**Вложения** (проекты, датапак `data/<ns>/tradery/village_projects/*.json`)

- Проект: стоимость, нужный уровень, эффекты. Оплачивает игрок со своего баланса (деньги сжигаются — главный сток); вкладчик получает репутацию, деревня — очки процветания. Каждый проект — один раз на деревню.
- Дефолтные: «Фонари на улицах» (150, ур. 1: шанс визита покупателей +10%; вдоль всех тёмных улиц деревни — уличные фонари: основание-стенка, столб из забора (в пустыне — песчаниковая стенка), на высоте 5 перекладина над дорогой и подвесной фонарь, под ним три свободных блока; не ближе 10 блоков друг к другу, не больше 48 на деревню; улица, где блочный свет уже ≥ 10 (ванильные фонари, факелы), пропускается; не у дверей, не в постройках, на настоящей земле под открытым небом; раз в день освещается то, что загрузилось или появилось позже; деревня без улиц получает до 8 простых столбов у колокола), «Амбар» (300, ур. 1: казна держит +50%, кошельки +1 день; у колокола строится амбар), «Мастерские» (500, ур. 2: ставки жителей ×1.2; у колокола строится мастерская с рабочими блоками), «Сторожевой пост» (600, ур. 2: у колокола строится деревянная вышка, рядом с ней железный голем, потери от рейда ×0.5), «Новый прилавок» (400, ур. 2: у колокола строится прилавок рынка с серверными автоматами), «Торговый двор» (1000, ур. 3: караваны чаще, рыночный день на день раньше; у колокола строится огороженный двор под навесом).
- Постройки (решение автора 2026-10-24: вложение должно быть видно): `structure: <имя>` в json проекта (с любым действием, кроме прилавка; `action: "structure"` — только постройка) — шаблон `structure/village/<тип деревни>/<имя>.nbt` в палитре типа (генерируются `tools/project_structures.py`), ставится как прилавок; `action: "street_lamps"` — столбы. Нет места — деньги не списываются.
- «Мощёные улицы» (250, ур. 2; идея автора 2026-10-24): все дорожки (`dirt_path`) деревни — по всей структуре деревни (все её куски плюс 4 блока), не меньше радиуса доски у колокола — мостятся камнем в стиле типа (булыжник с каменным кирпичом; пустыня — гладкий песчаник; тайга и снег — булыжник с замшелым), ямки в одну глубину и пропуски травы в одну клетку между улицами засыпаются; шанс визита +5 %. Раз в день замощённая деревня с загруженным колоколом мостит то, что загрузилось или появилось с тех пор. Незагруженные чанки не трогаются и не грузятся. Нет дорожек — деньги не списываются.
- Тропинка к улице: каждая новая постройка (проект или постройка деревни) получает дорожку от своего края до ближайшей улицы в 12 блоках — один поворот, по естественной земле в пределах блока по высоте; земляная, а в замощённой деревне каменная. Ванильную генерацию улиц мод не трогает.
- Куда ставить (как стоят ванильные дома): все столбцы пятна на одной высоте, верх прочный и сухой (дорожки и грядки не прочные — улицы и поля остаются), земля настоящая — три сплошных блока вглубь (крыша и навес снизу пустые), над пятном только воздух и трава, никого на месте, ни один столбец не внутри деревенской постройки (кусок структуры деревни выше улицы); сначала места рядом с дорожкой, потом любые. Фонарные столбы — то же плюс открытое небо. Постройка смотрит передом (север шаблона) на колокол.

**Деревня строит сама** (решение автора 2026-10-24, идея 1 из `docs/ideas.md`)

- Датапак `tradery/village_buildings/*.json`: `level`, `cost`, `structure`, `market` (шаблон с серверными автоматами — работает рыночный процессор). Дефолтные: «Колодец» (ур. 2, 200; табличка с названием деревни, знамя цвета типа), «Сторожевая башня» (ур. 3, 600; фонарь наверху), «Торговый дом» (ур. 4, 1500; три серверных автомата и доска).
- Пока есть что строить, `villages.buildings.savingsShare` (0.5) суточного дохода казны уходит в фонд строительства (`savings`, рейды его не трогают). Когда фонд покрывает стоимость и колокол загружен, деревня раз в день ставит постройку у колокола по тем же правилам, что проекты; нет места — завтра. Доска, подсказка колокола и Jade показывают «Копим на …: X / Y»; игроки рядом получают сообщение о постройке; процветание — как за проект той же стоимости.

**Праздник** (идея 7)

- В рыночный день деревни уровня ≥ `villages.festival.minLevel` (3) в час собрания жителей (9000–12000) один раз в день: колокол звонит, каждый житель деревни получает `walletBonusDays` (1) дней жалованья сверх кошелька, процветание +25, игроки в радиусе 64 видят заголовок «Праздник!» и сообщение, у колокола до ночи запускаются фейерверки.

**Жители-поставщики**

- Скупка игрока (`BUYBACK` за деньги) с галкой «Жители могут продавать» (та же галка `villagers`, подпись по режиму).
- Производство — датапак `data/<ns>/tradery/villager_supplies/*.json`: профессия → предметы и сколько житель производит за сутки (фермер — урожай, рыбак — рыба, пастух — шерсть, каменщик — камень и т. д.), ×1 + 0.25 за уровень профессии. Запас копится до `suppliers.stockDays` (2) суток.
- Житель-поставщик приходит к скупке, как покупатель (тот же менеджер, радиус, кулдаун): продаёт, если цена скупки ≥ честная × региональный множитель × `suppliers.minPriceRatio` (0.8). За визит — до `suppliers.maxLotsPerVisit` сделок из запаса, сколько позволяют место на складе и деньги владельца.
- Сделка атомарная, как у игрока-продавца: деньги владельца → кошелёк жителя (без потолка: заработал), предметы → склад скупки. Предметы создаются из запаса жителя (ограничены производством). `Reason` — `tradery:villager/supply`. Уведомление владельцу «Фермер продал 32 × Пшеница за 🪙6.00», офлайн-сводка.

**Торговля между деревнями**

- Тип деревни → датапак `data/<ns>/tradery/village_types/<type>.json`: `cheap` (предметы/теги, множитель < 1) и `dear` (множитель > 1). Например, пустыня: дёшево песок, кактус, терракота; дорого брёвна, шерсть, рыба. Тайга — наоборот по дереву.
- Региональный множитель меняет честную цену в этой деревне: для покупок жителей у лавок, для наград заказов и для цены, по которой жители-поставщики готовы продать. Вкладка «Рынок» показывает, что здесь дёшево и дорого.
- Караваны: деревня уровня ≥ 3 раз в `caravans.intervalDays` (3) отправляет караван в известную деревню другого типа не дальше `caravans.maxDistance` (1500) блоков. Караван появляется у колокола деревни назначения, когда она загружена и день: торговец (странствующий торговец с ламами, имя «Караван из …»), торгует в окне Tradery за валюту: продаёт дешёвое родной деревни, покупает дорогое здесь. Кошелёк каравана — из казны родной деревни. Уходит через `caravans.stayTicks` (12000).

**Рыночный день**

- Раз в N дней по уровню (днём). На доске — «через N дней», в день — сообщение игрокам в деревне.
- В рыночный день: шанс визита покупателей и поставщиков ×`marketDay.visitMultiplier` (3), лимит трат деревни ×2, караван, если подходит его срок, приходит в этот день.

**Торговое место**

- Через вкладку «Рынок»: лицензия на `villages.rent.days` (7) дней за `villages.levels.rentPerDay` по уровню (5 / 10 / 20 / 40) — в казну. Пока действует: к автоматам владельца в радиусе деревни жители этой деревни приходят из радиуса ×1.5 и с шансом ×`rent.visitMultiplier` (1.5); в рыночный день — первыми. Без лицензии всё работает как раньше.

**Угрозы**

- Ванильный рейд у колокола: проигран — процветание −`threats.raidLossProsperity` (30%), казна −50%, кошельки жителей деревни −50% (с `Сторожевым постом` — вдвое меньше); выигран — процветание +`threats.raidWinProsperity` (100 очков) и заказы на восстановление. Смерть жителя — процветание −1%; убит игроком — −3% и ванильная репутация.

**Удобство для серверов**

- Книга лавочника (`tradery:shop_ledger`, крафт: книга + золотой слиток; и `/tradery shops`): окно со списком своих автоматов — где, что, цена, остаток, ожидающая выручка, галка жителей; тревоги (пусто, нет места под оплату); «Показать» — луч частиц над автоматом на 30 с. Для незагруженных — последний известный снимок из индекса автоматов.
- Прилавок (`tradery:market_counter`): до 6 предложений в одном блоке (у каждого товар и цена), общий склад; окно покупателя со списком; жители выбирают нужное предложение.

```json5
// server.json5, новая секция (подсекции — чтобы уложиться в кодеки)

  censusIntervalTicks: 600, prosperityDecayPerDay: 0.05, treasuryPerVillager: 1, treasuryDays: 7, tradeTaxPercent: 10, boardRadius: 48,
  levels:    { thresholds: [0, 300, 1500, 5000], wageMultiplier: [1, 1.25, 1.5, 2], ordersPerDay: [3, 4, 5, 6],
```

## Безопасность и анти-дюп

Отсутствие дюпов — главная продающая фича: каждый сценарий покрывается тестом до релиза.

| Сценарий | Риск | Защита |
| --- | --- | --- |
| Автомат сломан, пока открыт GUI | Дюп товара/выручки | Меню закрываются на сервере при удалении BlockEntity; `stillValid` проверяет BlockEntity каждый тик |
| Два игрока покупают последний товар | Двойная выдача | Все покупки идут через серверный поток последовательно, остаток проверяется внутри транзакции |
| Спам `VendingBuy` | Лаг, гонки | Rate limit 10/с |
| Спам `VendingQuickTrade`, запрос издалека | Лаг, покупка через стену/издалека | Тот же rate limit 10/с; дальность взаимодействия игрока, чанк загружен, BlockEntity автомата на месте |
| Подделанный пакет с чужим `pos` | Покупка издалека, настройка чужого автомата | Дистанция ≤ 8, проверка открытого меню и владельца |
| Шифт-клик / хоткеи в GUI покупателя | Вытащить товар без оплаты | В GUI покупателя нет реальных слотов товара — только отображение |
| Нет места в инвентаре покупателя | Потеря товара или денег | Проверка места до списания; при нехватке — отказ |
| Воронки / трубы | Вытягивание склада | Блок не контейнер, capability/Storage нет |
| Взрыв, поршень, гравитация | Разрушение с дюпом | Неразрушаем для всех, кроме владельца и OP; `PushReaction.BLOCK` |
| Краш сервера посреди транзакции | Потеря денег, дюп при скупке | Изменения в одном тике; склад, балансы и инвентари участников пишутся на диск вместе (`TradePersistence`); лог — после коммита. Проверка: `tools/crash-test.sh` |
| Переполнение баланса | Отрицательные деньги | `Math.addExact`, потолок `maxBalance` |
| Руда в дробилках | Умножение монет | Не в `c:ores`, нет рецептов обработки |
| Мобы из спавнеров | Бесконечные деньги | `ignoreSpawnerMobs`, diminishing returns, `dailyCap` |

## Этапы разработки

Сначала API и ядро, потом то, где деньги тратятся, и только потом источники денег (без места, где тратить, баланс эмиссии не проверить). После каждого этапа — гейт: оба лоадера собираются и стартуют, тесты зелёные, `docs/PROGRESS.md` обновлён.

1. **Ядро.** API, экономика, хранение, лог, конфиги (JSON5), права, команды `/bal /pay /baltop /eco /tradery history|reload|hud`, пакеты, HUD. Гейт: unit-тесты, баланс переживает рестарт, HUD на обоих лоадерах.
2. **Вендинг.** Vending/display-блоки, GUI покупателя/владельца/админа, скупка, фасады, анимации, уведомления и офлайн-сводка, индекс автоматов. Гейт: все сценарии анти-дюпа в GameTest.
3. **Источники денег.** Монетная руда и генерация, монеты, withdraw/deposit, награды и антифарм, `/eco stats`. Гейт: GameTest руды и наград.
4. **Интеграции.** Common Economy API, Placeholder API, Jade, JEI, REI. Гейт: каждая опциональна, мод стартует без них.
5. **Релиз.** Полная локализация EN/RU, README, CI, публикация, чек-лист приёмки.
6. **v1.1 Living Market.** Жители-покупатели (кошельки, нужды, честные цены, спрос, репутация), торговля с жителями за валюту, деревня-экономика (казна, процветание, заказы, вложения, поставщики, караваны, рыночный день, аренда, угрозы), книга лавочника и прилавок, галка в GUI владельца, рынок деревни с менялой, конфиг и датапаки, 15 языков. Гейт: GameTests (покупка жителем атомарна и без дюпа, лимиты кошелька и деревни, цена выше порога не покупается, скупка и серверные автоматы не обслуживаются, спрос падает и восстанавливается, прилавок рынка генерируется с валидными предложениями; торговля с жителем за валюту: покупка списывает баланс в кошелёк, продажа платит из кошелька, пустой кошелёк, нехватка денег или предметов ничего не меняют, лимит сделки, «обменять всё», выключенный конфиг — ванильное окно), клиентский харнесс снимает жителя у прилавка и окно торговли. Деревня-экономика: перепись и процветание, казна, доска с заказами, вложения, жители-поставщики (атомарно, без дюпа), региональные цены и караваны, рыночный день, торговое место, рейды; книга лавочника и прилавок на несколько товаров — каждое с GameTests и кадрами харнесса; затем порты на 1.21.1 и 1.20.1.

## Изменения относительно ТЗ

1. `ResourceLocation` → `Identifier` (в 26.3 класса `ResourceLocation` нет).
2. `configured_feature` → `worldgen/feature` (переименовано в 26.3); loot tables используют `"modifier"` вместо `functions`. В ветке 1.21.1 — старые имена (`configured_feature`, `functions`).
3. Права на Fabric — встроенный в Fabric API `fabric-permission-api-v1` вместо `me.lucko:fabric-permissions-api` (LuckPerms 5.5.85 поддерживает оба).
4. Воронки: противоречие ТЗ («insert-only» vs «не отдаёт capability») решено в пользу «никакой автоматизации в MVP» (решение автора 2026-09-30).
5. EMI и WTHIT вынесены из MVP — сборок под 26.3 нет. Text Placeholder API явно добавлен в MVP (в ТЗ был только в таблице интеграций).
6. Единый формат Reason-идентификаторов `tradery:<категория>/<действие>` (в ТЗ были `tradery:mob_kill` и `tradery:reward/kill` одновременно).
7. API: добавлены `systemAccount`, `serverAccount`, перевод с комиссией, `formatPlain`, `isInfinite`/`isLocked`, текст причины в `Failure`; `Success` содержит сумму и комиссию.
8. Критерий «баланс переживает kill -9» переформулирован: консистентный откат к последнему сохранению без дюпа.
9. Добавлены хранилища: история, статистика и дневные счётчики, индекс автоматов, кэш имён.
10. Единицы в конфигах — основные; `decimals` фиксируется за миром.
11. Сравнение предметов в `ITEM`-режиме — строгое по компонентам.
12. Руда: начисление через loot table; нет денег в креативе и без подходящего инструмента; поведение при `dailyCap`; формула `inflationDamping`; учёт наличных в обороте.
13. `/tradery hud` — серверная подкоманда, переключающая HUD пакетом (нет конфликта клиентского и серверного корня `/tradery`); добавлены `/eco lock|unlock`.
14. Дублирование событий в `NeoForge.EVENT_BUS` вынесено из MVP.
15. Публикация — `mod-publish-plugin` вместо mc-publish.
16. Тулинг — как в ТЗ (fabric-loom + ModDevGradle); раскладка по MultiLoader-Template 26.3, папки модулей без префикса `tradery-`.
17. Восстановлен список этапов MVP (в экспорте ТЗ он потерялся).
